Bias Auditor for hiring models

A SHAP-powered tool that detects proxy discrimination: bias against a protected group that shows up even when the group's label is never a model input.

Type
Personal project · explainable AI
Stack
Python, scikit-learn, SHAP, Streamlit, Pandas
Data
Synthetic, with bias built in on purpose
Links
Live demo ↗ · GitHub ↗

The problem

Companies rightly don't feed gender, race, or age into hiring models. But a model can still discriminate if another feature acts as a proxy: it correlates closely enough with group membership to carry its signal indirectly. A real-world example is career-gap length, which correlates with gender because of unequal caregiving leave. A model that penalizes career gaps can end up penalizing one gender more, without ever "knowing" gender.

About the data. The dataset is synthetic. I built a realistic historical hiring dataset with this bias baked in, so the audit has something real to find. This demonstrates an auditing method. It is not a claim about any real company's hiring.

What the audit does

  1. Trains a model on historical hiring outcomes using only legitimate-looking features (experience, education, skill scores, interview scores, career-gap length). Gender is deliberately left out.
  2. Checks outcome disparity with the four-fifths rule, the standard U.S. EEOC heuristic for adverse impact: if one group's selection rate is under 80% of another's, that is a red flag.
  3. Uses SHAP to find the source by comparing each feature's average contribution across gender groups, which shows which feature is acting as the proxy.
  4. Suggests fixes: removing the proxy, reweighting, group-aware thresholds, and ongoing monitoring.

Why I built it

Most explainable-AI projects stop at "here is what the model thinks is important." This one asks the harder question: is what the model learned actually fair? That turns interpretability from a nice-to-have into a governance tool. It also matters for regulation: the EU AI Act sets requirements around bias and discrimination for high-risk AI systems, which include AI used in employment.

Scope and limits

The project demonstrates one well-known form of bias (proxy discrimination), one fairness metric (the four-fifths rule), and one explainability method (SHAP). Real fairness auditing is broader. It also looks at metrics like equalized odds and calibration, at intersectional bias across several protected attributes at once, and at legal frameworks that vary by country. This is a working demonstration of the core technique, not a complete compliance solution.
